# MuseFlow 产品需求文档

版本 `v0.2` · 更新于 `2026-09-20` · 状态：产品范围与 P0/P1 已由用户确认，具体规则仍为设计草案。

本文定义课题十二的产品边界及验收口径。课程依据见[课程要求](COURSE_REQUIREMENTS.md)。用户已确认仅围绕题目列出的四类模块和三项创新点开展工作，接受 P0/P1 划分，当前不固定交付日期，并要求文本、音乐、TTS 供应商可切换。下文未明确确认的价格、框架库和实现细节仍为提案，不表述为教师规定。

## 产品目标

让没有专业音乐制作经验的用户在一个工作区内，通过自然语言表达创作意图，调用歌词、音乐和语音工具，持续修改作品，并管理结果和消耗额度。系统根据用户的创作与反馈提供下一次创作灵感。

一次完整体验是：注册登录 → 描述创作意图 → Agent 提议工具及参数 → 用户确认积分消耗 → 后台生成 → 试听和归档 → 反馈偏好 → 获得新的推荐。每次执行应能追溯到请求、工具、任务、产物和积分流水。

项目完成目标是覆盖对话式 Agent、推荐、生成物管理、用户与双积分计费四类模块，并展示 Agent 串联创作、行为反哺推荐和 SaaS 用户/计费/后台设计。基础权限、任务状态和计费一致性用于支撑这些功能；商业运营规模、复杂订阅和额外运维体系不作为课题完成条件。

## 用户与权限

| 角色 | 目标与权限 |
| --- | --- |
| 访客 | 查看介绍、注册和登录；不能调用付费工具或读取用户作品 |
| 创作者 | 管理自己的对话、任务、作品、声音资料、偏好、账户和积分 |
| 平台管理员 | 管理账户状态、工具可用性、权益/价格版本、额度调整和运行记录；操作写审计记录 |

首轮以一个用户对应一个个人工作空间作为隔离边界；组织、团队共享创作和组织账单不在本课题范围内。管理员不能因角色而默认浏览所有私人歌词、音频和声音样本；需要处理内容时另行设计最小权限和审计流程。

## 设计范围与实现批次

- **P0 首轮实现，已接受**：注册登录、对话工作区、歌词/音乐/TTS 工具、异步任务、音频与封面管理、基础推荐、双积分、后台、基础权益和使用记录。
- **P1 后续实现，已接受**：翻唱、声音克隆及其声音样本、授权与档案管理。P1 是实现顺序，不是从课题中删除这些能力。
- **课题外可选扩展，不作为 P1 必做或验收条件**：AI 封面生成、订阅或充值沙箱、可撤销的公开分享。这些曾列入初稿 P1，本次按“只完成题目内容”的范围限定调整；封面的归档、检索、筛选与下载仍属于 P0。
- **不纳入当前范围**：训练基础音乐模型、专业多轨编辑、实时合奏、开放交易市场、真实支付结算、跨组织协同及无人审核的自动公开发布。

P0/P1 是已接受的实现顺序，不是课程原文的优先级，也不绑定日历期限。产品范围已可用于设计和开发，不以课程材料中的实现要求表述冲突为开工前置问题；课程报告和提交要求仍单独追踪。完成 P0 可以演示核心流程，完整课题功能完成还需补齐 P1。

## 功能需求

| 编号 | 需求和主要业务规则 | 可观察的验收结果 |
| --- | --- | --- |
| FR-01 | 账户与隔离：注册、登录、退出；账户可被停用；后端从会话获取用户身份，对每个资源做归属检查 | 两个账户不能互读对话、任务、下载链接或钱包；停用账户不能新建任务 |
| FR-02 | 对话工作区：保存会话历史；支持创作意图澄清、工具提议、参数预览和确认；模型只从工具注册表选择允许的工具 | 用户能看到实际执行的工具、任务状态和产物；纯文本回复不会创建成功任务 |
| FR-03 | 创作工具：P0 实现歌词生成、文本生成音乐、TTS；P1 实现翻唱和声音克隆；修改已生成结果通过新任务产生新版本 | 支持的工具产生可读歌词或可播放音频，并记录来源和版本；不可用工具清楚标示原因 |
| FR-04 | 异步任务：排队、运行、未知结果、成功、失败、取消；刷新后可继续查询；重试关联原任务 | 重复确认不重复创建收费任务；超时不误报失败后再次收费；失败信息给出可行下一步 |
| FR-05 | 生成物管理：统一记录歌词、音频和封面；按标题/歌词文本检索，按类型、风格、日期、状态筛选；支持预览、下载、重命名与删除 | 音频可播放下载，封面可展示下载；作品关联原会话/任务；删除后不再可访问或被推荐 |
| FR-06 | 推荐闭环：推荐允许展示的素材和灵感；基于创作标签、试听、收藏及“不感兴趣”事件；给出推荐理由并支持重置偏好 | 同一候选集下，反馈前后排序按规则变化；不会推荐其他用户私人作品；无历史时使用通用标签入口 |
| FR-07 | 双积分：分别展示两类余额和流水；执行前报价、冻结，成功交付后结算，明确失败或成功取消后释放 | 并发扣费不透支；重复事件不重复扣费；每笔变化可追溯到任务或管理员调整 |
| FR-08 | 管理后台：账户启停、工具能力与可用性、价格/权益版本、任务概况和人工异常处理；额度调整必须填写原因 | 普通用户无后台权限；后台显示结果未知和长期冻结的任务；调整与状态变化留存审计记录 |
| FR-09 | 声音授权：翻唱只接受用户声明有权使用的输入；克隆前明确记录声音使用授权和样本来源；可撤销声音档案 | 未满足授权前置条件时不能建任务；撤销后不能继续新建克隆/合成任务；支持禁用和删除路径 |
| FR-10 | SaaS 权益与用量：账户关联权益方案；限制工具、单次时长和并发数；展示历史用量；课设通过后台发放演示额度 | 超额度/并发/权益限制在调用 Provider 前拦截；模拟额度标明演示性质；真实支付不显示为已接入 |
| FR-11 | 供应商可切换：文本、音乐、TTS 分别配置适配器、服务地址、模型和凭据引用；业务工具使用稳定接口 | 对已实现适配器的切换不修改页面或业务流程；能力不匹配明确拒绝；旧报价和在途任务绑定原配置 |

FR-01～FR-11 的接口、数据与测试分别在[接口契约](API_CONTRACT.md)、[数据模型](DATA_MODEL.md)和[测试计划](TEST_PLAN.md)中展开。FR-11 是用户明确提出的接入要求，用于支撑题目的生成工具，不扩展产品功能类别。

## 工具输入与输出

| 工具标识 | 输入 | 输出 | 依赖与边界 |
| --- | --- | --- | --- |
| `lyrics.generate` | 主题、语言、风格、结构、可选已有歌词 | 可编辑的结构化歌词 | 文本模型；歌词版本单独保存，不修改既有音频 |
| `music.generate` | 提示词、可选歌词版本、风格、时长选项 | 音频及可验证的元数据 | 音乐服务；人声/纯音乐/语言等能力以适配器能力表为准 |
| `speech.synthesize` | 文本、已允许的音色、语言、语速选项 | 语音音频 | TTS 服务；使用克隆音色时额外校验声音档案状态 |
| `music.cover` | 有使用权限的源音频、目标音色 | 翻唱音频 | P1；确认服务确实支持后才开放，不用 TTS 冒充翻唱 |
| `voice.clone` | 授权记录、声音样本 | 可引用的声音档案与试听产物 | P1；档案属于当前用户，服务支持撤销/删除的能力需验证 |

输入长度、可选时长、文件大小和格式通过服务端能力表返回，由实际 Provider 接入验证后锁定；前端不得承诺未支持的参数。多步请求可逐步生成“歌词 → 音乐”，每个收费步骤分别报价确认。P0 不让 Agent 在后台无限追加任务。

人工编辑歌词保存为新版本并保留来源，不消耗生成积分；AI 改写则创建新的歌词生成任务。音乐生成明确引用用户选定的歌词版本，既有音频不会随文本编辑而改变。

文本、音乐、TTS 各自具有稳定业务接口，通过配置选择已实现的供应商适配器；未知协议需要增加适配器，不承诺只改服务地址就能兼容所有供应商。开发可先使用明确标识的 Mock 完成联调，再接入实际账号进行真实验证。能力选择、配置快照和切换规则见[接口契约](API_CONTRACT.md#provider-内部契约)。

## 双积分业务提案

课程只提出“双积分计费”，没有规定两类积分的名称和用途。本提案暂定 `creation` 创作积分与 `voice` 语音积分：歌词、音乐、翻唱、封面工具使用前者；TTS 和声音克隆使用后者。每个工具动作只从一个积分账户扣费，两类积分不互换、不转赠、不抵扣。

价格使用版本化规则；首轮建议按能力表中的固定规格报价，报价在 10 分钟内有效。消耗数值、初始赠送额度、方案权益和真实采购成本均待确认。界面展示“本次预计消耗”“当前可用”“冻结中”，不把冻结显示为已扣除。

仅在产物已入库且可访问，或声音档案已成功建立时结算。结果未知时保持冻结并进入查询/人工核对，不自动重试收费动作。关闭网页不取消任务；具体状态和取消规则见[创作与积分流程](WORKFLOWS.md)。

## 页面与交互

| 页面 | 必需内容 | 空态、加载和错误处理 |
| --- | --- | --- |
| 注册与登录 | 注册、登录、会话退出、错误提示 | 登录失败不泄露账户详情；停用状态给出联系路径 |
| 创作工作区 | 会话列表、对话、参数卡、报价确认、任务卡、播放器 | 缺参数时澄清；余额不足可返回调整参数；任务状态从服务端恢复 |
| 作品库与详情 | 检索筛选、封面、音频、歌词、来源、下载、删除 | 无作品时提供创作入口；下载失效可重新授权；删除前确认 |
| 灵感推荐 | 候选卡、理由、标签、试听、收藏、不感兴趣 | 无偏好时选标签；无合适素材时给可编辑灵感，不伪造作品 |
| 积分与用量 | 两类余额、冻结、流水、方案限制、用量 | 未接入支付时不提供真实付款入口 |
| 声音档案 | 样本来源、授权、处理状态、音色引用、撤销 | P1；未接入时说明限制；撤销后隐藏后续使用入口 |
| 管理后台 | 用户、工具、权益、价格版本、异常任务、调整记录 | 敏感操作确认原因；不输出密钥；失败时保留待处理状态 |

## 非功能需求与验收目标

下列要求用于保证课题功能可用，尚未实测；测试时记录环境、Provider 和配置。生成耗时受外部服务影响，不能套用普通接口的响应目标。压力规模和备份演练可作为额外评估，不作为课题范围的附加门槛。

| 编号 | 目标 | 验证口径 |
| --- | --- | --- |
| NFR-01 | 资源隔离、密钥保护和最小权限 | API/下载/回调/后台负向用例全部通过；密钥不进入仓库、浏览器和普通日志 |
| NFR-02 | 任务和计费可恢复、一致且幂等 | 重复提交、重复回调、乱序事件、Worker 中断、结果未知时账本不重复变更；详见创作与积分流程 |
| NFR-03 | 基础交互性能 | 在实际演示数据量下记录查询耗时和错误，生成任务异步返回状态、不阻塞页面；初稿的 20 并发/1 万作品/P95 ≤ 1 秒仅保留为可选压力评估参考 |
| NFR-04 | 可观察性 | 请求、Agent 步骤、任务、Provider 请求、流水可通过关联 ID 追踪；日志默认不包含样本原文和完整私人内容 |
| NFR-05 | 可维护性和可复现 | 适配器有统一输入输出及契约测试；他人可按运行说明初始化数据并执行核心演示；配置缺失时明确报错 |
| NFR-06 | 可用性和可访问性 | 主要流程支持键盘操作、有清晰标签与状态文本；音频不强制自动播放；窄屏可完成确认、试听和下载 |

## 产品完成定义

首轮完成需要 P0 需求有实现与证据、核心异常分支通过、所有未接入能力明确标示。至少完成一次真实 Provider 的“歌词 → 音乐 → 归档”以及一次真实 TTS 调用，才能声明相应真实能力已验收。若只有 Mock，应称为流程演示，不能勾选真实服务验收。

完整课题设计覆盖所有 S-01～S-04；完整课题功能完成需要 P0 与 P1 的五类创作工具、推荐闭环、音频/封面管理、注册登录、双积分和后台均有对应证据。供应商可切换先通过契约与切换测试验证，每种对外宣称可用的真实能力另需真实请求验证。报告、测试记录和演示视频必须使用同一版本边界。
