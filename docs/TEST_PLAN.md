# 测试与验收计划

当前采用根目录 Nuxt 应用，任务服务由 MF-08 在 `server/` 内实现，不预设独立 Worker。以下任务持久化、幂等与恢复要求仍须满足；具体调度、回调、查询及恢复触发方式依据 Provider 能力确定，租约仅在采用相应执行机制时适用。

状态：计划，**所有功能测试均未执行**。当前没有业务代码或测试报告。本文定义应验证什么、如何记录证据以及何时可以宣称完成。

## 测试层次

功能是否「完善」的操作性判定（八个测试维度、各层方法分工、五条准入标准、常见遗漏点与可复制检查清单）见 **[功能完备性检查清单](FUNCTION_READINESS_CHECKLIST.md)**。本文定义要验证什么，该清单定义怎么系统地验证以及何时可以宣称完成。

已于 2026-09-20 确认采用 Vitest + Nuxt Test Utils，不引入 Playwright。自动化目标覆盖领域规则、API/数据库、Provider 契约及 Nuxt 集成；浏览器关键流程采用手动验收，用例、环境与实际结果证据记录在对应 Issue/PR。MF-04 已建立 `pnpm test`、`pnpm test:integration` 和 `pnpm test:db`，当前只覆盖骨架与基础兼容性，不等于以下业务 T-xx 已通过。

MF-03 另建立 **`pnpm test:contract`**（`mock/providers/check-contract.ts`），无需框架、网络、账号或数据库，验证三类端口的统一结果语义、能力声明完整性、能力不匹配样例 CM-01 ~ CM-12 与配置快照路由规则。它是契约自检，**不代表任何真实供应商能力已验收**。

| 层次 | 验证内容 | 依赖 |
| --- | --- | --- |
| 领域单元测试 | 价格快照、积分状态转换、权限判定、推荐规则 | Vitest；固定样例和可控时间，不访问外部 Provider |
| API/数据库集成 | 事务原子性、并发幂等、资源隔离、迁移、任务并发派发 | Vitest；Nuxt API 使用 Nuxt Test Utils；真实 PostgreSQL，不用内存对象代替并发账本验证 |
| Nuxt 组件与应用集成 | 组件交互、状态展示、页面与服务端集成 | Vitest + Nuxt Test Utils；不替代真实浏览器手动验收 |
| Provider 契约 | schema、能力边界、拒绝/未知/成功、查询和取消 | 可控 Mock；每个真实适配器另做真实请求验证 |
| 浏览器手动端到端验收 | 登录、对话确认、刷新恢复、试听下载、后台 | 实际浏览器与前后端；记录步骤和结果；服务未接入时清楚区分 Mock 演示 |
| 非功能与交付 | 演示性能、日志脱敏、视频和打包；压力与备份恢复演练可选 | 固定版本与可记录环境，不增加课题外的运营验收门槛 |

## MF-02 页面基线验收

MF-06/07/09/10/14/15 对照 `prototype/` 与 [UI 原型交接说明](UI_PROTOTYPE.md) 检查本项布局、信息层级、关键交互及键盘/窄屏行为；使用 Nuxt UI 实现，必要差异在 PR 中说明。检查模拟数据与操作已由真实接口替换，加载、空态、错误、权限及任务状态准确，正式页面不保留原型的场景控制、演示角色切换和手动推进任务。MF-16 汇总验证，不以原型演示或 Mock 测试替代真实业务验收。原型未覆盖的页面先补设计再验收。

## Agent 与推荐专项记录

对话流专项验证 AI SDK 原生 UI 消息流的文本/工具事件、Nuxt/Vue transport 和历史重载；重复 clientMessageId 不重复调用模型，断线或重启留下的消息能标明中断，刷新后查询原任务。流开始前后分别验证 HTTP 错误和流内错误，确认流内工具提议或客户端伪造结果不能创建收费任务。协议和服务端行为用 Vitest/Nuxt Test Utils 验证，浏览器交互按手动验收记录。

首轮准备至少 12 条固定创作案例，覆盖完整需求、缺参、修改歌词、多步骤、工具不可用、余额不足、越权作品引用、授权缺失和供应商异常。记录预期工具/动作、实际选择、参数校验、是否正确等待确认，以及产物和流水是否匹配。测试不要求模型每次使用相同自然语言。

推荐至少准备 3 类可解释偏好案例，固定候选、规则版本和事件顺序，比较前后排序。邀请团队成员试听时将“风格符合度、音频可播放性、主观喜好”分开记录；未实施评价前不写准确率、满意度或用户增长数字。

## 演示脚本

1. 介绍课题、3 人分工和本次已实现范围，明确演示使用真实服务还是 Mock。
2. 登录创作者账号，展示两类积分与权益。
3. 输入创作意图，展示 Agent 选择工具、歌词生成、确认音乐报价、生成状态和结果。
4. 试听音频、查看歌词与封面、检索和下载作品；展示可追溯任务和积分流水。
5. 使用 TTS，说明其独立积分类型。
6. 收藏或不感兴趣，展示下一次推荐变化及理由。
7. 演示一个明确失败释放或结果未知核对案例，以及管理员对应记录。
8. 展示设计范围与实现差异；若实现 P1，再演示翻唱/克隆的授权及撤销。

长任务可剪辑展示，但保留同一 taskId 和前后状态；不得把预录音频伪装为当前请求的实时结果。视频时长原文未规定，按内容和 50M 大小限制实际安排。
